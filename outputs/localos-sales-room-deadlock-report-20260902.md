## Root cause

The request path executes CREATE TABLE/CREATE INDEX statements inside the same transaction that later writes sales_room_events and updates sales_rooms. Concurrent requests acquire relation locks in opposing DDL/DML order.

## Approved fix

Removed request-time schema DDL from all public sales-room handlers and from the shared event writer; Alembic remains the sole schema owner.

**Why this is causal:** The public transactions now acquire only their normal DML locks, removing the opposing relation-lock order that produced the deadlock.
