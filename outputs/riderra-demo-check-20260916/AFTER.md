## Что исправлено

- Показанный одиночный пост сохраняется в существующем серверном контексте диалога вместе с версией. Последующая команда переписывает этот черновик, сохраняет дату и историю; конфликт версии блокирует запись. После списка уточняется выбор.
- Явное пожелание, жалоба или идея руководителю сохраняются в существующем журнале. Ответ отражает сохранение и действительные права разбора. Гипотезы не превращаются в факты. Пустая очередь получает ответ без модели.
- Явное еженедельное расписание рассчитывается кодом. Даты 1/8/15/22 ноября 2026, квоты 2/1/1 проверяются до сохранения. Поддержан текст SpeechKit без пунктуации. Старые планы не изменяются.
- Приветствие без выполненного изменения не считается успехом. Один ограниченный повтор вычисления; успешно выполненные шаги не повторяются.
- Генерация поста явно отключает лишний режим рассуждений. До изменения реальные переписывания занимали 20–66 секунд; после — 5,0 и 5,4 секунды в контрольном production-проходе. Это измерения, не гарантия времени.

## Оставшиеся ограничения

- Telegram: во время проверки были ConnectError. Через настроенный прокси API доступен, прямое соединение не удалось. Опрос бота восстановился (возраст heartbeat 3 секунды), но это не подтверждает доставку пользовательского голосового сообщения. Новый реальный входящий Telegram на момент проверки не поступал. Telegram-показ нельзя считать проверенным.
- iOS/Android и микрофон устройства не проверены. Пользователю предложен контрольный запрос с телефона. Эти пункты остаются обязательными перед голосовой демонстрацией.
- Доставка срочного уведомления и дневной сводки реальным получателям в этом выпуске не тестировалась; проверена постановка и права.
- Точное расписание в новом обработчике поддерживает один пост в неделю; для другой частоты запрашивается уточнение. Реальный период хранится в существующем JSON и границах дат, поле тарифного горизонта использует допустимое значение 14/30/60/90 из текущего ограничения БД. Миграция не выполнялась.

## Короткий сценарий демонстрации

1. Выбрать Riderra. «Покажи последний пост в контент-плане целиком».
2. «Придумай вместо него рекламный пост про Пхукет со ссылкой https://riderra.com/ru». Это меняет черновик, поэтому для показа использовать заранее выбранный демонстрационный материал.
3. «Тест демонстрации: пожелание клиента — получать номер машины заранее. Передай администратору». Открыть Рабочий журнал → На разбор; затем отменить тестовую запись.
4. «Покажи жалобы, пожелания и идеи сотрудников на разбор».
5. Для создания отдельного тестового плана: «Создай контент-план с 1 ноября 2026 на четыре недели: один пост в неделю, два про Таиланд, один про Китай, один про Танзанию. Старый не удаляй». Проверить даты и темы.

Не представлять Telegram/телефон как проверенный канал, пока не выполнен реальный проход на устройстве показа.
