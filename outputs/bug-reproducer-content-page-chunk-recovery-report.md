## Root cause

ContentPage was imported directly while DashboardLayout and SettingsPage already used one-shot recovery. After deployment removed the old hashed chunk, ContentPage could not refresh onto the current entry bundle.

## Approved fix

Wrapped only the ContentPage lazy import in the existing loadRouteWithRecovery helper with the route label контента.

**Why this is causal:** The wrapper catches a rejected or timed-out ContentPage import, performs one cache-busting navigation, and prevents reload loops through the existing session guard.
