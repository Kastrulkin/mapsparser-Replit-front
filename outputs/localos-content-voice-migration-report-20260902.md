## Root cause

CREATE TABLE IF NOT EXISTS does not reconcile columns on an already existing table, but the migration immediately created an index requiring user_id.

## Approved fix

Idempotently restore user_id, example_type, and example_text before creating indexes; keep fresh-database NOT NULL definitions unchanged.

**Why this is causal:** The missing columns are restored before the exact failing index statement, allowing the same migration fixture to complete without changing existing rows.
