# Фото и видео из папки клиента — beta

Владелец открывает **Контент → Медиатека → Материалы с Диска**. Участники используют материалы согласно доступу к контенту. Импорт доступен бизнесам из `DISK_IMPORT_BUSINESS_IDS`; первый бизнес — «Органика».

Яндекс: существующее разрешение `cloud_api:disk.app_folder`, входящая папка `app:/LocalOS/<business>/Входящие`. Исходящее резервирование остаётся самостоятельным. Google: отдельный служебный аккаунт с ролью «Читатель» на папке клиента; ключ загружается суперадминистратором на `/dashboard/settings/storage`. JSON-ключ шифруется существующим серверным ключом, API возвращает только адрес и версию. Личное OAuth `drive.file` не расширяется. Делегирование организации не используется.

Для Google владелец делится папкой с адресом аккаунта, вставляет ссылку и создаёт пустую подпапку с одноразовым кодом (30 минут). После проверки нажимает «Включить автоматическое добавление». Одну корневую папку нельзя привязать к разным бизнесам. Ярлыки пропускаются.

Worker проверяет активные источники каждые пять минут. Каждая страница и файл — долговечное задание общей очереди; интерактивный worker их не забирает. Состояние обхода фиксируется в той же транзакции, что и задания файлов. Временные ошибки повторяются с задержкой. Потеря доступа приостанавливает источник. Возобновление проверяет доступ, новая версия подключения отменяет старые задания.

Фото JPG/PNG/WebP до 10 МБ сохраняются в существующей медиатеке; HEIC/HEIF преобразуются в JPEG. Ограничение изображения — 40 мегапикселей, результат также до 10 МБ. Повтор одного файла/редакции идемпотентен, одинаковое содержимое сопоставляется по хешу внутри бизнеса. Новое содержимое не заменяет фото в старых постах. Импорт не запускает исходящее резервирование или создание постов.

Видео MP4/MOV/WebM остаётся на Диске. В карточке доступны название, размер, формат, длительность при наличии и ссылка на оригинал. Видео можно выбрать для неопубликованного материала контент-плана через интерфейс или общий Оператор. Выбор сбрасывает прежнее подтверждение; все пути автоматической публикации блокируются для выбранного видео. Размещение выполняется вручную после проверки текста и файла. Для открытия оригинала сотруднику требуется доступ средствами провайдера. Токены в браузер не передаются, публичные ссылки не создаются.

Исчезновение отмечается только после полного успешного обхода и повторной проверки корня. Недоступные материалы исключаются из новых подборов, выбранные ранее сохраняются с предупреждением. Отключение прекращает импорт и исключает источник из нового выбора; история и локальные копии сохраняются.

## Контракт

Маршруты: `/api/media-intelligence/disk-import`, `/prepare`, `/verify`, `/action`, `/videos`, `/videos/select`, `/google-reader`. Настройки источника — только владелец/суперадминистратор; настройка ключа — только суперадминистратор. Все запросы перепроверяют активность пользователя и бизнес. `action` требует версию источника, выбор видео — версию материала.

Исходники: `src/services/disk_import.py`, `disk_import_providers.py`, `disk_import_media.py`, `src/api/disk_import_api.py`. Миграция: `20260915_disk_import`, родитель `20260915_storage_oauth`. Входящие данные не являются инструкциями Оператору.

## Выпуск и приёмка

Перед миграцией — свежий `pg_dump -Fc`, успешное полное чтение `pg_restore`, SHA-256. Частичное обновление текущих production-файлов с проверкой их хешей сохраняет чужие изменения. Для HEIC требуется `pillow-heif` в обычном worker и app. Откат: очистить allowlist импорта и перезапустить затронутые сервисы; таблицы и медиатеку не удалять.

Автоматические проверки используют отдельную PostgreSQL и подменённые ответы провайдеров. Они не заменяют подключения реальных аккаунтов: для приёмки нужны добавление фото/видео через оба Диска, появление в течение десяти минут при исправных провайдерах, проверка удаления/повтора, затем три рабочих дня пилота. Большой первичный архив обрабатывается порциями и может занять больше десяти минут.
