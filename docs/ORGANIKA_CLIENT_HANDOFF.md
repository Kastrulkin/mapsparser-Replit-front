# Органика: состояния и очередь сотрудников

Статус: beta — реализовано и проверено в production на внутренних тестовых диалогах «Органики». Автоответы выключены.

## Рабочая цепочка

- Приветствие → уточнение потребности → подбор услуги → ответ на вопрос.
- Намерение записи → booking_request → очередь сотруднику: CRM-запись не подменяется внутренней заявкой.
- Просьба человека, жалоба, возврат или медицинская безопасность → waiting_for_staff; запись в очередь и пауза сохраняются одной транзакцией.
- Сотрудник с действующим operations.write нажимает «Взять диалог» → human_active. Повторное принятие другим сотрудником отклоняется.
- Завершение → closing; агент остаётся на паузе. Завершает принявший сотрудник или superadmin.

Состояние рабочего диалога хранится в aiagentconversations.current_state. События передачи/принятия/завершения содержат actor в aiagentmessages. Повторная передача одного диалога не создаёт второе событие. Сообщения клиента на паузе сохраняются для сотрудника, но модель не отвечает. Поздняя запись состояния не может снять паузу.

## Поверхности

`/dashboard/agents?section=clients&view=handoffs` — внутренняя очередь сотрудников LocalOS. Это реальная передача в кабинет, а не уведомление в Telegram и не доказательство прочтения сотрудником.

Кнопка «Проверить передачу без клиента» создаёт явно помеченный внутренний тестовый диалог. Принятие и завершение меняют реальные PostgreSQL-записи, тестовый ответ сохраняется в истории. Ни клиентских отправок, ни изменения ai_agents_config это не вызывает.

Обычная вкладка «Проверка ответов» остаётся dry-run: состояния переигрываются по истории без записи реального обращения. Реальную передачу надо проверять отдельной кнопкой, чтобы избежать ложного сообщения «сотрудник вызван».

## Ограничения

- Telegram/WhatsApp-уведомления сотруднику не подключались; подтверждение означает запись в очередь LocalOS.
- У Органики не принят внешний канал ответа клиенту. Отправка реальному клиенту из переданного диалога блокируется с объяснением; публикационный telegram_chat_id не используется как клиентский получатель.
- Тестовый ответ разрешён только для test-handoff:* и принятого диалога; существующие права команды не расширяются.
- Автоответы выключены на уровне настроек бизнеса, а каждый переданный диалог дополнительно приостановлен.
- Новые таблицы создаются Alembic-ревизией 20261030_client_dialogues после полной резервной копии PostgreSQL. Downgrade не удаляет историю.

Реализация: services/client_dialogue_state.py, services/client_chat_handoff.py, chats_api.py, ai_agent.py; UI — ClientHandoffInbox.tsx.
