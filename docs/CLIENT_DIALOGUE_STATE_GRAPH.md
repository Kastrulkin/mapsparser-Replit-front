# Схема состояний клиентского диалога

Статус: beta, production, 30.10.2026. Автоответы Органики выключены.

## Источник истины

`services/client_dialogue_state.py`: next_state и dialogue_graph используют единый упорядоченный RULES; ручные переходы берутся из STAFF_TRANSITIONS, используемого services/client_chat_handoff.py. Схема не компилируется из свободного текста workflow и не меняет работу агента.

- Общая схема: `/dashboard/agents?section=clients&view=states`.
- Текущий этап и история: граф в выбранном обычном диалоге и во вкладке «Сотруднику».
- Graph API: GET `/api/business/<business_id>/client-dialogue-graph?conversation_id=<id>`; существующее право operations.write, проверка принадлежности диалога бизнесу, 403/404 без чужих данных.
- Узлы и условия — runtime-правила; отдельная ветка: пожелание записи → очередь сотруднику → сотрудник подключился → завершение.
- needs_attention помечен как зарезервированный: реального автоматического входа пока нет.

## Запись истории

Новые смены состояния сохраняются событием dialogue_state в aiagentmessages в той же транзакции, что обновление aiagentconversations. Передача хранит from/to в handoff_requested; принятие и завершение — существующие handoff_accept/handoff_close. Неизменное состояние не создаёт новый переход. API возвращает до 500 последних событий в хронологическом порядке и явно отмечает усечение.

Прошлые отсутствующие события не восстанавливаются по сообщениям или догадкам. Поэтому у старых тестовых диалогов история может быть частичной, хотя текущий этап известен.

## UI

Переиспользован AgentWorkflowGraph / ReactFlow. Compiled-автоматизации продолжают передавать прежние steps; клиентский граф передаёт собственные nodes/edges. Выбранный/текущий узел виден крупно; «Вся схема» показывает обзор, доступны масштаб и панорамирование. Пройденные узлы и рёбра выделяются по сохранённой истории. Есть текстовый список переходов, условий и текущего этапа для доступности.

На паузе не показываются как доступные автоматические выходы текущего завершённого диалога. Ветка сотрудника и записанный путь сохраняются на схеме. Смена бизнеса очищает приватный снимок; опрос обновляет состояние каждые 15 секунд. Ошибки схемы не ломают экран диалога.

## Приёмка

- 35 профильных backend-тестов, включая соответствие схемы правилам runtime.
- UI: граф, история, смена scope, некорректный API-ответ, совместимость прежнего графа и compiled-конструктора.
- TypeScript и production build успешны.
- В браузере Органики создан внутренний тест: начало → очередь → сотрудник подключился → завершение; текущий узел и история обновились, пауза сохранилась.
- Проверен отдельный внутренний runtime-диалог с полной историей: начало → уточнение → подбор услуги → ответ → очередь → сотрудник → завершение.
- Настройки бизнеса не изменялись, внешних сообщений не отправлялось.
