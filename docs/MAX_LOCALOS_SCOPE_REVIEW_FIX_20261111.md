## Поведение

- Выбор LocalOS означает всю платформу. Отправка и история чата, общий обработчик owner-бота и выбор системного бизнеса используют одну область доступа.
- Существующий бизнес `localos-platform-telegram-radar` служит контекстом обработки и истории; `LOCALOS_PLATFORM_BUSINESS_ID` может указать другой существующий системный бизнес. Пользователь и бизнес должны быть активны, право superadmin проверяется в БД. Название LocalOS само по себе прав не даёт; новые бизнесы не создаются.
- Запрос входящих показывает до пяти сохранённых человеческих ответов аутрича по всем бизнесам, включая workstream без campaign. Показаны даты последней синхронизации отправителей и наличие ошибок без раскрытия внутренних сообщений. Новая синхронизация почты/мессенджеров не запускается, и ответ явно об этом сообщает.
- Запросы сохранённых данных из системного контекста могут читать активные клиентские, внутренние и demo-бизнесы. Обычный бизнес сохраняет свою область доступа; отправки, публикации и изменения используют существующие проверки и подтверждения.
- Плашка проверки называет результат, объясняет следующий шаг и открывает связанный раздел. Продолжение контент-плана открывает бизнес результата и новый план по его ID. Переход ничего не подтверждает и не публикует. Ожидание решения показано без процентов и вращающегося индикатора.

## Реализация

- `src/services/operator_platform_context.py`: текущие права и чтение входящих/сводки.
- `src/services/telegram_control_scope.py`, `src/api/operator_api.py`, `src/telegram_bot.py`: единый контекст платформенного чата в miniapp и owner-боте.
- `src/services/operator_core.py`, `src/services/operator_query.py`: платформенные запросы сохранённых данных.
- `src/services/operator_async_jobs.py`, `frontend/src/lib/mobileDataClient.ts`: структурированная внутренняя цель результата с бизнесом и ID плана.
- `frontend/src/components/telegram/JobProgressSheet.tsx`, `frontend/src/pages/telegram/TelegramControlWorkspace.tsx`: понятное состояние проверки и переход; отправка из LocalOS без выбора отдельного бизнеса.
- `frontend/src/features/telegram/useContentResult.ts`: открытие плана по ID результата с сохранением существующего календаря и истории планов MAX-ветки.
