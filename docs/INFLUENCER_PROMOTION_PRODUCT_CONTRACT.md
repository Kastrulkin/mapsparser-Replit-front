# Продвижение через локальных авторов: продуктовый контракт MVP

Статус: `beta`, закрытый пилот. Внешнее название продукта: LocalOS.

## Пользователь и задача

Основной пользователь — владелец локального бизнеса или специалист, ведущий бизнес клиента. Его задача — найти небольшое число релевантных локальных авторов, безопасно согласовать размещение и отделить наблюдаемые результаты от подтверждённых бизнесом.

Успех сценария: пользователь получает объяснимый shortlist, утверждает условия, готовит коммуникацию в существующем supervised-outreach контуре, фиксирует публикацию с proof и видит происхождение каждой метрики.

## Термины

- Автор — человек с публичной площадкой и собственной редакционной ролью.
- Авторский канал — площадка, в которой содержание определяется одним автором или устойчивой небольшой командой.
- Сообщество — локальная площадка без обязательной персональной авторской идентичности.
- Медиа — редакционная площадка с регулярными публикациями.
- Агрегатор — площадка, собирающая локальные предложения, события или места.
- Источник — публичная страница, канал, документ или медиакит, из которого получен проверяемый факт.
- Получатель — конкретный публичный контакт, выбранный для коммуникации. Источник не становится получателем автоматически.

## Границы MVP

Доступны:

- поиск по уже разрешённым публичным источникам LocalOS;
- ручное добавление публичной ссылки;
- импорт до 500 кандидатов из CSV/JSON в текущий поиск;
- асинхронное поисковое задание с восстановлением зависшего worker-процесса;
- детерминированный скоринг `creator-fit-v1`;
- shortlist и кампании;
- подготовка контакта через `prospectingleads` и workstream `creator_collaboration`;
- коллаборации, ожидаемые материалы, proof и snapshots метрик;
- приватная авторская комната без регистрации: ответ на предложение, изменения, публикация и авторская статистика;
- ручное подтверждение условий и результатов.

Ограничения:

- закрытые сообщения и личные данные не используются как публичное доказательство;
- предположительные совпадения площадок не объединяются автоматически;
- изменение суммы, формата, срока или прав инвалидирует предыдущее подтверждение;
- LocalOS не выполняет платежи;
- отправка, публикация и действия от имени бизнеса требуют существующего ручного approval;
- права на повторное использование не подразумеваются;
- приватная ссылка действует 30 дней; в базе хранится только её SHA-256 hash, повторное создание инвалидирует старую ссылку;
- расчётная эффективность не называется подтверждённой выручкой.

## Разрешённые источники пилота

- подключённые `knowledge_sources` с публичным URL;
- публичные документы из knowledge layer;
- публичные Telegram-каналы и страницы контактов;
- публичные сайты и медиакиты;
- ссылка, вручную добавленная пользователем.

Импорт CSV/JSON, VK-каталоги, события и расширенное обнаружение из репостов относятся к следующей итерации поиска.

## Скоринг

Итоговый балл рассчитывается LocalOS и сохраняется вместе с версией и объяснением:

| Компонент | Вес |
| --- | ---: |
| Локальность | 30% |
| Соответствие аудитории | 25% |
| Качество вовлечения | 15% |
| Соответствие формата | 10% |
| Свежесть | 10% |
| Коммерческая готовность | 10% |

Количество подписчиков не является отдельным доминирующим фактором. Неизвестные данные сохраняются как неизвестные, а не как отрицательный факт.

## Статусы и ручные границы

- Поиск: `created → searching → enriching → checking → ready / partial / failed`.
- Кампания: `draft → needs_review → approved → active → completed` с возможностью паузы или отмены.
- Коллаборация: `draft → invited → replied → negotiating → agreed → visit_scheduled → awaiting_content → published → measuring → completed`.
- Материал считается опубликованным только при наличии URL или ручного proof; затем он отдельно получает статус проверки.

Подтверждение условий не отправляет сообщение. Подготовка контакта создаёт рабочий контекст, но возвращает `external_messages_sent: 0`.

## Данные и tenant boundaries

Публичный канонический профиль и публичные evidence могут переиспользоваться между поисками. Кампании, shortlist, коллаборации, коммерческие договорённости, контакты и метрики всегда связаны с `business_id`. API проверяет доступ к бизнесу на каждом приватном запросе.

## Критерии приёмки

- Новый сценарий находится в «Продвижении», а не в «Контенте».
- Старый сценарий партнёрств и его адрес продолжают работать.
- Непилотный клиент не видит новый раздел и не может вызвать закрытые API-возможности.
- У каждого результата есть версия скоринга, причины и provenance.
- Без утверждённых условий нельзя подготовить outreach.
- Подготовка outreach не отправляет сообщение.
- Изменение условий требует нового подтверждения.
- Метрики содержат источник и confidence; подтверждённая выручка отделена от наблюдаемых показателей.
- Платежи, массовая отправка и автономная публикация отсутствуют.

## Отложено

Расширенные платформы, договоры, выплаты, прогноз бюджета и marketplace-механика остаются последующими релизами.
