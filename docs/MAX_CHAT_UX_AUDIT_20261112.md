# MAX: отправка в чате и обнаружение почты

Дата: 12 ноября 2026. Статус: локальные исправления; production не проверен и не обновлён.

## Цель и критерий завершения

Пользователь переносит ежедневную работу в LocalOS. Почты уже подключались к аккаунтам; разработка и диагностика велись из текущего чата, чтобы довести продукт до самостоятельной работы. Эти подключения нужно использовать в существующем контуре LocalOS. Доступность Gmail в текущем чате и отдельные исправления интерфейса не являются приёмкой цели.

Из Web и миниаппа MAX должны работать отправки, проверки аутрича, контент, другие поддерживаемые задачи и настройка автоматизаций. После настройки исполнение и сохранение результатов не должны зависеть от открытого чата разработки.

| Сценарий приёмки | Критерий результата в LocalOS |
| --- | --- |
| Почта Riderra | Найдено существующее подключение `riderracs@gmail.com`; видны бизнес, состояние, последняя проверка и конкретная причина блокировки при её наличии |
| Новый поиск лидов | Условия и стоимость → предусмотренное подтверждение → запуск → состояние → сохранённые компании и результат |
| Отправка | Действующий отправитель нужного бизнеса → черновик и условия → существующее разрешение/согласование → реальная отправка и её статус без дубля |
| Проверка аутрича | Обновление подключённых источников → дата и охват проверки → реальные новые ответы; сохранённые данные и свежая проверка различаются |
| Контент | Подготовка → правки → согласование → поддерживаемая публикация либо явно обозначенная ручная передача → сохранённый результат |
| Автоматизация | Источник, условия, расписание, лимиты и согласования настраиваются в LocalOS; доступны история, ошибки и остановка |
| Продолжение работы | После закрытия и повторного открытия MAX сохраняются поручение, решение, результат и принадлежность бизнесу; повтор не создаёт вторую отправку |
| Область LocalOS | Действующий администратор управляет всеми разрешёнными бизнесами; каждый результат и каждая отправка сохраняют конкретный бизнес |

Первый контрольный проход — существующий аккаунт Riderra и его подключённая почта, целиком через LocalOS/MAX. Прямой запрос к Gmail из чата разработки не заменяет ни одного шага. Затем проверяются контент и настройка автоматизации. Приёмка внешних отправок и платных действий сохраняет существующие границы подтверждения; диагностическая проверка сама по себе их не разрешает.

Готовность каждого полного сценария пока не подтверждена на production. Локальные тесты отдельных компонентов и исправление обнаружения почты не закрывают этот критерий.

## Что подтверждено

- Локальный проект Mac снова доступен. SSH-чтение production отклонено ограничениями текущего сеанса; запрос на повышение разрешений автоматически отклонён. Утренние сообщения пользователя не прочитаны.
- История Operator сохраняется в `operatorconversations` и `operatormessages`, с отдельными business/user/channel. Это наличие механизма, а не доказательство получения конкретного утреннего сообщения.
- Подключение Gmail `Riderracs` успешно вернуло профиль `riderracs@gmail.com`. Это проверка подключения данного чата; она не доказывает текущую авторизацию почты в LocalOS.
- В LocalOS есть конфигурация отправителя Riderra в `riderra_template_authorization_service.py`. Текущий статус строки отправителя в production не проверен.
- До исправления `sendOperator` добавлял пользовательское сообщение лишь после HTTP-ответа и ожидания фоновой задачи. Интерфейс не показывал текст во время отправки; кнопка оставалась визуально доступной.
- `settings.check_connections` читал только `externalbusinessaccounts`. Реестр отправителей `outreach_sender_accounts` не попадал в наблюдение Operator. Это подтверждённый пробел обнаружения; его связь с конкретным утренним ответом ещё не доказана.

## Принятое устройство чата

Один основной столбец: переписка и поле ввода. Настройки города/валюты остаются в настройках. Голос, вложения и дополнительные материалы доступны в раскрытии «Голос и файлы».

| Момент | Что видит пользователь |
| --- | --- |
| Нажатие отправки | Свой текст сразу и «Отправляется…» |
| Сервер подтвердил приём | «Получено LocalOS»; очередь/работа внутри одного ответа |
| Получен итог | Тот же ответ обновляется результатом |
| Нет подтверждения получения | Явное неопределённое состояние, возврат текста, повтор с прежним request_id |
| Ответ принят, но результат не загрузился | Подтверждение получения сохраняется; интерфейс не утверждает, что действие не выполнялось |
| Длинный завершённый ответ | Краткое начало и «Подробнее» на том же месте |
| Нужно согласование | Полный текст условий и кнопки решения; условия не скрываются |
| Есть старое фоновое задание | Компактная строка; окно хода работы открывается по нажатию |

Прямой переход к готовому результату сохраняет его business/item. Смена области очищает частное состояние; поздние ответы старой области отбрасываются. Ввод следующего вопроса не стирается при завершении предыдущего.

## Обнаружение почты

`operator_connection_status.py` объединяет сохранённые внешние подключения и отправителей аутрича. Обычная область ограничена выбранным бизнесом. Для платформенной области заново проверяются действующая роль superadmin и активность пользователя/системного бизнеса в БД.

Поиск по названию бизнеса или адресу использует SQL-параметры. Пустой результат поиска с фильтром и обрезанная выдача не считаются доказательством отсутствия подключения. Статусы отключения, разрешение аутрича, синхронизация ответов и дата последней синхронизации остаются разными фактами.

Секреты, настройки авторизации и исходные ошибки провайдера не выбираются. Проверка не подключает ящик заново, не читает всю почту и ничего не отправляет. Синхронизация ответов аутрича не равна доступу ко всем письмам ящика.

## Основания для упрощения

- [AWS Cloudscape: Generative AI loading states](https://cloudscape.design/gen-ai/patterns/generative-ai-loading-states/): текстовый статус в месте будущего ответа, различие обработки и готового результата.
- [NN/g: AI chatbot design guidelines](https://www.nngroup.com/articles/ai-chatbots-design-guidelines/): раскрытие деталей на месте, короткая переписка и сохранение позиции чтения.
- [GOV.UK Chat: mobile interface research](https://insidegovuk.blog.gov.uk/2026/08/19/designing-gov-uk-chat-for-the-gov-uk-app/): сокращение вводного текста и лишних элементов на телефоне, ясное поведение отправки и ожидания.

Это применение опубликованных рекомендаций, а не проведённое нами пользовательское исследование.

## Проверки и границы

Проверки:

- Vitest: 41 тест прошёл в 6 файлах (MAX, Telegram, отправка/получение, очередь, повтор с прежним request_id, смена области, согласования и раскрытие длинных ответов).
- Pytest: 37 прошли, 1 упал; все 7 новых тестов обнаружения подключений прошли. Падение `test_deepseek_receives_complete_scoped_contract_for_required_tools` (`output_schema`) отдельно воспроизведено с сохранённым исходным `operator_core.py` до изменений.
- Production Vite build прошёл.
- TypeScript: 31 диагностическое сообщение до изменений и 31 после; новых нет. Это не успешный полный typecheck.
- Компиляция Python и отсутствие новых хвостовых пробелов проверены.

Полный production-проход и визуальная приёмка на устройстве MAX остаются непроверенными. Запуск headless Chromium в текущем сеансе остановлен macOS sandbox (`MachPortRendezvousServer: Permission denied`); снимки экрана не получены.

Новые потоковые ответы, новые подключения, изменение прав на почту и production-записи не выполнялись. Для выкладки нужен точечный пакет с сохранением более новых изменений production; синхронизировать весь текущий рабочий каталог нельзя.
