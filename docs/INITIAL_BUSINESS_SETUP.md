# Первичная настройка компании в LocalOS

Статус `beta`. По умолчанию функция выключена.

Сотрудник с доступом суперадмина открывает «Первичная настройка» у существующего аккаунта или «Подготовить кабинет» в карточке лида. При создании нового кабинета в админке чат открывается после сохранения нового кабинета. Несвязанный лид можно подготовить от имени сотрудника. При неоднозначном совпадении сотрудник выбирает существующий кабинет сам. В самостоятельной регистрации компания попадает в настройку после подтверждения почты. Приглашение связывает заранее подготовленный кабинет с данными владельца.

Пользователь видит исходные данные, состояние сайта, каждой карты и каждой социальной ссылки, разбор каталога и этап проверки. В чат можно вставить ссылку, указать «Конкурент: ссылка», «Вид деятельности: …» или «Услуга: название | описание». Без карт и сайта можно продолжить с тем, что уже есть в профиле, и указанным видом деятельности. Прогресс сохраняется для компании между сессиями.

Ссылка, отправленная в чате первичной настройки выбранной компании, запускает чтение и подготовку черновика. Явная команда об этой настройке со ссылкой в рабочем чате запускает тот же процесс. После чтения LocalOS разбирает услуги, подбирает запросы по сохранённой статистике и проверяет фото. По итогам доступен PDF с предложениями, источниками и ссылками на разделы кабинета. Его можно скачать до согласования. Документ доступен только пользователям с доступом к компании.

Команда проверяет черновик и нажимает «Сохранить кабинет». За одно действие LocalOS добавляет прочитанные карточки и сайт, заполняет пустые поля профиля при единственном подходящем значении, сохраняет услуги с предложенными вариантами и факты с источниками. Приглашение можно подготовить после сохранения.

- Сайт и соцсети, указанные в карточке самой компании, добавляются в список источников и проверяются автоматически. Сайт читается существующим сборщиком публичных контактов. Из него используются контакты, описание, структурированный каталог и найденные ссылки на социальные площадки. Публичный Telegram читается существующим сборщиком. Для остальных соцсетей в этой версии сохраняются ссылки.
- После чтения сайта SEOmator проверяет заголовки, описания, H1, canonical, мобильный viewport и ограничения поисковых роботов в полученном HTML. В чате раскрывается список проверенных страниц и предлагаемых правок. При вводе адреса главной проверяются до трёх страниц, прочитанных сборщиком. При вводе конкретной страницы проверяется только она. Для компании без сайта шаг пропускается. На ранее прочитанном сайте нажмите «Провести SEO-аудит сайта». Обновление аудита не пересчитывает каталог и семантику.
- Снимок соотносится с конкретной карточкой. Яндекс и 2ГИС читаются существующими парсерами. Если штатный парсер не прочитал карточку компании на Яндекс Картах, LocalOS автоматически использует резерв Apify по той же ссылке. Лимит $0,02, один запуск на кабинет без платных повторов. Расход относится к LocalOS. В чате во время обеих попыток отображается сбор данных. Для Google используется подходящий снимок или подключённая карточка с совпадающей ссылкой. Адрес жилого дома сам по себе отображается как ссылка.
- Семантика строится из каталога и вида деятельности. Для каждой услуги LocalOS ищет подходящие фразы с частотностью в Wordstat. Если сохранённых данных нет и Wordstat подключён, LocalOS проверяет названия в Wordstat с ограничением числа запросов за один разбор. Темы без подтверждённой частотности показаны отдельно. При сохранении кабинета подходящие фразы добавляются в карточку услуги, исходные названия и описания сохраняются рядом с предложенными. Сравнение по добавленным конкурентам показывает подтверждённые показатели и названия услуг со снимков одной площадки.
- Факты после сохранения доступны в «Знаниях о бизнесе» и учитываются при подготовке контента. Профиль, услуги, семантика, знания и сравнение открываются из чата либо через обычное меню.
- Сотрудник проверяет получателя перед подготовкой доступа. Новый владелец сам задаёт пароль по одноразовой ссылке. Ссылка выдаётся сотруднику для самостоятельной передачи. Действия в LocalOS не публикуют изменения на картах и не отправляют письма или сообщения владельцу.

## Контент после сохранения кабинета

Чат проверяет сохранённый план, фото в медиатеке, тексты и подключения. Владелец может открыть каждый раздел из чата и вернуться к текущему шагу. Темы учитывают действующие факты из «Знаний о бизнесе» и услуги. В плане сначала утверждаются темы, затем в календаре готовятся и проверяются тексты.

После сохранения LocalOS подбирает компании в радиусе двух километров по реестру и ищет блогеров по городу в каталоге. При пустой выборке компаний возможен один ограниченный запуск поиска по картам. Если подходящих блогеров нет, в LocalOS создаётся задача для команды.

В чате можно подтвердить или дополнить факты, ввести текст или надиктовать его, подключить папку с фото, утвердить темы и подготовить, отредактировать и утвердить тексты. Опубликованные посты учитываются по их статусу, в том числе по явной отметке о ручной публикации.

Владелец на тарифе «Управление» может включить следующий план после завершения предыдущего. Планировщик ждёт, пока все оставшиеся темы опубликованы. Для каждого завершённого плана готовится один черновик на утверждение. Публикация остаётся отдельным действием.

## Развёртывание пилота

Состояние хранится в миграции `20261122_initial_business_setup`. Для включения необходимы код на веб-сервере и обработчике фоновых задач, собранный интерфейс и переменные окружения в обоих процессах. После резервной копии базы применить миграции, установить `LOCALOS_INITIAL_SETUP_ENABLED=true` и ограничить пилот перечислением существующих идентификаторов в `LOCALOS_INITIAL_SETUP_BUSINESS_IDS`. `LOCALOS_INITIAL_SETUP_LEAD_IDS` задаёт доступные карточки лидов. При ограниченном списке компаний новый черновик из незнакомого лида не создаётся. Сначала определите или подготовьте нужный кабинет и добавьте его идентификатор в когорту. Отключение флага скрывает сценарий и останавливает новые чтения, сохраняя ранее принятые данные.

SEO-аудит использует закреплённую версию пакета `@seomator/seo-audit` из `src/website_seo/package-lock.json`, которую устанавливает сборка образа. При запуске проверок используются только данные от текущего сборщика. В каталоге действий OpenClaw доступно исследование сайта для партнёров. Оно не выполняет правила SEOmator над готовым HTML, поэтому эти правила выполняются внутри LocalOS. Для локальной проверки нужно выполнить `npm ci --omit=dev --omit=optional --ignore-scripts` из `src/website_seo`. Для старого образа при частичной выкладке установите зависимости из того же lockfile и положите Node из закреплённого этапа сборки в `src/website_seo/node_modules/.bin/node`. Скрипт синхронизации сохраняет этот каталог на сервере. Новый образ включает Node и SEOmator.

Первые компании — Хамик и Jinlian Vegan Ice Cream. Для Хамика используйте его тип аренды и фактический адрес, даже если публичной карточки пока нет. Для Jinlian используйте существующий кабинет и проверьте исходный каталог, свойства снимка и сохранение предложений. Остальных клиентов добавляйте после проверки пилота.

См. [правила реестра компаний](COMPANY_REGISTRY_OPERATIONS.md), [границы действий](agents/capabilities.md) и [проверки локального пилота](../tests/test_initial_business_setup.py).
