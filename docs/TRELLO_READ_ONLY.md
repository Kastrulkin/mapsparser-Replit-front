# Trello: подключение только для чтения

Дата: 28 октября 2026. Статус: `beta / deployed read-only pilot`; настройка OAuth ожидается.

## Пользовательский результат

Владелец бизнеса или superadmin открывает **Настройки → Подключения → Trello**,
предоставляет доступ для чтения, выбирает до 10 досок и загружает карточки выбранной
доски по кнопке. Доступны открытые и архивные карточки, список, срок и отметка
выполнения срока. В интерфейсе показываются первые 100 карточек снимка; сервер
сохраняет весь полученный снимок в пределах лимита 20 000 карточек на доску.

Карточки не превращаются автоматически в задачи LocalOS, лиды или кампании.
Оператор, фоновые задания, webhooks и внешние изменения в этот выпуск не входят.
Безопасность доступа намеренно ограничена владельцем/superadmin: права сотрудников
и коммерческое тарифное правило нужно согласовать перед расширением пилота.

## Этап 0: решения и доказательства

- Переиспользованы существующие `externalbusinessaccounts`, Fernet-шифрование,
  контекст сессии, компоненты интерфейса и реестр подключений.
- 28 октября выполнено только чтение `openclaw skills info trello --json` на
  `openclaw-prod`. Установленный bundled skill не готов: отсутствуют
  `TRELLO_API_KEY` и `TRELLO_TOKEN`. Проверенный 27 октября контракт содержит
  shell-примеры REST с общей парой переменных окружения, без контракта
  multi-business OAuth/refresh/синхронизации. Живой каталог LocalOS тогда содержал
  два действия, без Trello. Отсутствие действия в каталоге не приравнивается
  к отсутствию самого skill.
- Причина тонкого собственного адаптера: изолированные подключения бизнесов,
  OAuth 2.0, одноразовые попытки входа и сохранённые снимки не обеспечиваются
  проверенным skill. Новый исполнительный контур не создаётся. Будущие внешние
  изменения должны проходить существующие approvals/Action Orchestrator.
- Выбран confidential OAuth 2.0 client приложения **вне Power-Up**. Scopes строго
  `read:board:trello offline_access`; расширенный grant, включая write scopes,
  отклоняется. Данные участника и email не запрашиваются.
- Используется token endpoint `https://auth.atlassian.com/oauth/token`: он указан
  в списке endpoints и исполняемых примерах официального руководства. В отдельных
  абзацах того же руководства есть лишний `/authorize`. Реальное подтверждение
  протокола тестовым приложением пока не выполнено.
- При проверке локального `.env` необходимые Trello OAuth-настройки отсутствовали.
  Приложение Trello и реальная тестовая доска не создавались и не подключались.

## Контракт реализации

| Маршрут | Назначение |
| --- | --- |
| `GET /api/business/<id>/trello/status` | Состояние подключения, настройки, выбранные доски |
| `POST /api/business/<id>/trello/authorize` | Начать OAuth; вернуть URL без токенов |
| `GET /api/trello/oauth/callback` | Одноразовый callback, привязанный к браузеру и сессии |
| `GET /api/business/<id>/trello/boards` | Прочитать доступные доски |
| `PUT /api/business/<id>/trello/selection` | Сохранить выбор в LocalOS после проверки через Trello |
| `POST /api/business/<id>/trello/boards/<board_id>/sync` | Прочитать доску и атомарно сохранить полный снимок |
| `GET /api/business/<id>/trello/boards/<board_id>/snapshot` | Прочитать сохранённый снимок после проверки доступа к доске |
| `DELETE /api/business/<id>/trello/connection` | Удалить секрет и снимки из LocalOS, отменить незавершённые попытки |

Локальные POST/PUT/DELETE не изменяют объекты Trello. Единственный исходящий POST —
обмен/обновление OAuth-токенов. REST-транспорт допускает только GET по фиксированному
списку маршрутов на `api.trello.com`. Подписки webhooks не создаются; grant при
локальном отключении не отзывается удалённо. Его можно отдельно отозвать в Trello.

OAuth: PKCE S256; случайный state, в БД только его хеш; HttpOnly SameSite=Lax cookie;
10 минут; проверка актуальной LocalOS-сессии и владельца до сохранения. Повторный
callback отклоняется. Перезапуск входа и отключение отменяют старые попытки,
в том числе callback, ожидающий ответа OAuth-сервера.

Токены и PKCE verifier шифруются. При отсутствии криптографии или явно заданного
секрета подключения недоступны. Refresh сериализован блокировкой записи аккаунта;
новый refresh token сохраняется до дальнейших запросов, чтобы ошибка чтения не
откатила его ротацию. После этой фиксации повторно проверяются бизнес-доступ и
неизменность подключения. Неопределённый результат refresh требует переподключения.

Снимок заменяется только после полного чтения всех страниц. При неполном ответе,
повторяющейся странице или превышении лимита старый снимок сохраняется. При
подтверждённой потере доступа закрытые данные скрываются; отсутствующие в актуальном
списке доски удаляются из выбранных снимков. Текст провайдерских ошибок и токены не
передаются в журнал/браузер. Ответы API имеют `Cache-Control: no-store`.

Синхронизация ручная, синхронная, одна доска за запрос. При `429` или временном сбое
пользователь повторяет её позже; автоматические повторы и мониторинг квот пока не
реализованы. Между запросами разных страниц Trello не гарантирует транзакционный
снимок. Последовательное чтение подтверждает завершение обхода, а не общую версию
всех карточек в один момент времени.

## Локальная настройка и проверка

Нужны `TRELLO_READ_ENABLED=true`, `TRELLO_OAUTH_CLIENT_ID`,
`TRELLO_OAUTH_CLIENT_SECRET`, `TRELLO_OAUTH_REDIRECT_URI` и действующий
`EXTERNAL_AUTH_SECRET_KEY`. По умолчанию пилот выключен. Настройки окружения и
Docker Compose этим изменением не включаются и не модифицируются.

Callback регистрируется точно как `/api/trello/oauth/callback` на origin тестовой
инсталляции. HTTPS обязателен, кроме localhost/127.0.0.1 для разработки. Прокси
должен скрывать query callback из access logs. Секреты вводятся только в защищённые
настройки окружения, не в Git и не в чат.

Миграция: [20261028_trello_read_only](../alembic_migrations/versions/20261028_trello_read_only.py).
Создаёт попытки OAuth, снимки и уникальность подключения Trello на бизнес.
Миграция проверена дважды на отдельной локальной PostgreSQL с минимальной схемой
предшественников; полный upgrade существующей installation пока не принят.
На production миграция применена 28 октября после полной резервной копии; текущая ревизия `20261028_trello_read_only`.

Проверки: [транспорт и авторизация](../tests/test_trello_read_only.py),
[PostgreSQL и конкуренция](../tests/test_trello_read_only_pg.py),
[пользовательский сценарий и stale/error состояния](../frontend/src/components/TrelloConnectionPanel.test.tsx).
PostgreSQL-тесты требуют явного `TRELLO_TEST_DSN` и допускают только отдельный
локальный тестовый сервер, указанный в fixture. DATABASE_URL приложения не используется.

Результат локальной проверки 28 октября:

- 33 Python/PostgreSQL-теста и 6 frontend-тестов прошли.
- Ruff, проверка типов изменённого UI и отдельная production-сборка панели прошли.
- Chromium: выбор доски → сохранение → загрузка карточек на тестовых ответах API;
  настольный и мобильный размеры, без ошибок выполнения, горизонтального
  переполнения и нарушений WCAG 2 A/AA в автоматической проверке axe.
- Общие `typecheck` и сборка всего frontend не прошли: существующий модуль
  `GoogleContentAutomation` импортирует отсутствующий `OperatorPhotoPreview`;
  также есть ошибки типов в существующих тестах контента и аудита карт.
  Эти файлы в рамках Trello не изменялись.
- Проверка графа Alembic сохраняет две ветки: существующий
  `20261005_children_hair_salon_type` и продолженную ветку
  `20261028_trello_read_only`. Их объединение не выполнялось.

2. Пройти настоящий вход, отказ, refresh и отзыв grant; сверить доску с Trello.
3. Проверить реальные доски с архивом и более 1000 карточек, включая пагинацию.

Запись в Trello, webhooks и автоматическая синхронизация
требуют следующих согласованных этапов. Реальный OAuth-вход и чтение тестовой доски пока не приняты.
