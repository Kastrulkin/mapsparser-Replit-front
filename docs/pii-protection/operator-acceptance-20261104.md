# Синтетическая приёмка Оператора и Telegram — 04.11.2026

Статус: `internal`, интеграция установлена под выключенным флагом. Рабочий
`PII_PROTECTION_ENABLED=false`, серверный барьер `synthetic_only=true` сохранён.
Изменений рабочей схемы БД и бизнес-записей не выполнялось.

## Реализовано

Общий обработчик веба и Telegram при включённой защите повторно проверяет доступ
к бизнесу и читает до пяти последних публичных снимков `cards`, связанных через
`businessmaplinks` с тем же бизнесом и URL. Принимаются название и адрес известных
HTTPS-карточек Яндекс/Google/2ГИС. Пользовательский payload, ответ модели и частный
профиль бизнеса не назначают публичных исключений.

Публичные значения добавляются в отдельный участок окончательного prompt
планировщика с точными диапазонами. Совпадения в частном сообщении и истории
исключения не получают. Контекст привязан к бизнесу и пользователю и очищается
после запроса. При выключенном флаге загрузчик публичных снимков не вызывается.

Email при включённой защите проходит через PII, без прежнего обхода через `@refN`.
Серверные ссылки на ID сохранены. Восстанавливаются только строковые поля
проверенных контрактов; вложенный объект вместо текста отклоняется.

| Инструмент | Разрешённые поля | Граница выполнения |
| --- | --- | --- |
| partnerships.list_leads | query | чтение |
| competitors.list | name | чтение |
| communications.draft | message | внутренний черновик |
| partnerships.prepare_message | partner_name, business_name, draft_text | внутренний черновик |
| communications.prepare_send | message | подготовка подтверждения |
| finance.prepare_transaction | description | подготовка подтверждения |
| settings.prepare_user | email, name | подготовка подтверждения |

Назначение списка проверяет точное имя, класс риска, требование подтверждения
и тип поля в серверной схеме. Для остальных инструментов список пуст.
Scope, URL, название инструмента, права, канал и аудитория из PII не восстанавливаются.
Внешняя отправка, изменение доступа и финансовая операция сохраняют существующее
ручное подтверждение. Публикации и отправки в приёмке не выполнялись.

## Нагрузка и готовность

Действует общий token bucket **10 protect/с**, на бизнес — **4 protect/с**,
burst 4. Квота проверяется до NLP и Redis mapping; отказ — HTTP 429 с
`PII_RUNTIME_RATE_LIMITED` и `Retry-After: 1`. Оператор предлагает повторить запрос
позже. Вызова LLM и plaintext fallback при отказе нет. Разрешение уже выданных
токенов не расходует квоту распознавания.

Счётчики находятся в единственном worker, защищены lock и хранят не более 1024
HMAC-идентификаторов бизнеса. Неактивные записи очищаются, перезапуск сбрасывает
квоту. Это ограничение текущего одного процесса, не долговечный биллинг и не
готовый распределённый лимитер для нескольких реплик.

При первом нагрузочном прогоне проверка обычного темпа не прошла; фазовые данные
тогда не сохранялись. Сохранение замеров исправлено. Отдельный холодный запуск
воспроизвёл 4 ответа `PII_RUNTIME_BUSY` на 120 запросов при 8/с.
Добавлен прогрев до готовности: распознавание и точное восстановление двух
синтетических RU/EN-строк через настоящий зашифрованный Redis. При ошибке прогрева
процесс не становится готовым. Тестовые mapping имеют обычный TTL.

Окончательный образ — `localos-pii-runtime:20261104-v3`. Ключи, ACL и Redis
сохранены; отдельный синтетический mapping восстановился после обновления образа.

## Сквозные проверки

**61 модульная/регрессионная проверка, 18 сквозных проверок — без ошибок и пропусков.**
Из 18 сквозных проверок 13 повторены на окончательном v3. Корпус из 200 сценариев
прогнан через оба настоящих HTTP-адаптера LLM, направленных на локальные макеты,
и общий TLS-распознаватель с настоящими piighost/Presidio, RU/EN-моделями и Redis.

Использованы настоящий Flask-маршрут `/api/operator/chat`, Telegram dashboard
и `handle_text`, общий `process_chat`, маршрутизатор, планировщик и журнал
в отдельной временной PostgreSQL. Проверены фактические HTTP-payloads, отсутствие
исходных имени/email у макета LLM, сохранение публичного названия, отображение
восстановленного ответа, внутренний черновик, подготовка подтверждения, отказ
в запрещённом поле, чужой пользователь, повтор без повторного исполнения и
отключённый путь без чтения публичных снимков. Исчерпание настоящей HTTP-квоты
дополнительно проверено через веб: вызовов макета LLM — 0.

Границы имитации: LLM работает как loopback HTTP mock; каталог в сквозном профиле
сужен до двух проверяемых инструментов; исполнители черновика/подготовки отправки
подменены синтетическими обработчиками. Настоящие отправки, биллинг и все остальные
бизнес-сценарии не объявляются проверенными этим профилем. Голос, файлы и прочие
legacy/мультимодальные маршруты сохраняют [прежние границы](architecture.md).
