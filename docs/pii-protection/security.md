# Границы безопасности пилота

Статус: `internal`, production-включение не рекомендовано.

Обновление 03.11.2026: отдельный общий runtime и приватный Redis развёрнуты на VPS,
TLS/ACL/Fernet/TTL и отказы проверены на синтетике и под нагрузкой. После явного
разрешения подключены приложение, три обработчика и Telegram-бот под выключенным
флагом; у каждого проверены общий PID и отсутствие локальных NLP-моделей.
[Результаты и оставшиеся границы](shared-runtime-20261103.md),
[подключение и проверки клиентов](shared-wiring-20261103.md).

## Модель угроз

Недоверенными считаются пользовательский текст, документы, история, результаты
поиска и инструментов, ответы модели, JSON и плейсхолдеры. Провайдер LLM находится
вне доверенного контура. Соответствия остаются в LocalOS. Разрешение на чтение
записи/выполнение действия проверяется существующими сервисами LocalOS отдельно
от распознавания PII и отдельно от решения модели.

| Угроза | Мера и проверка |
|---|---|
| Чужой tenant/session/user | HMAC scope из трёх идентификаторов; тесты отрицательных доступов и параллельных запросов |
| Поддельный/старый токен | Проверка грамматики, текущего набора выданных токенов и scope; пользовательские токены запрещены на входе |
| Выгрузка Redis | Fernet ciphertext, HMAC ключей, отдельный секрет; TTL и проверка возраста ciphertext |
| Сбой/таймаут детектора или Redis | Ошибка `PII_*`, ноль вызовов провайдера до успешной подмены; plaintext fallback отсутствует |
| Потеря mapping после ответа | Ответ блокируется, произвольное восстановление/новая попытка с оригиналом не выполняется |
| Prompt injection → произвольный инструмент | Tool allowlist/схема и существующие права; отдельные разрешённые поля восстановления; writes требуют approval |
| Tool call в обычной JSON-генерации | Блокировка, без автоматической подмены аргументов |
| Утечка через исключение | Только фиксированный код ошибки; тест с чувствительным текстом в исключении |
| Утечка через upstream tracing | NoOpTracer для piighost, включая недетектированный текст; payload-redactor включён дополнительно |
| Скрытая сеть распознавателя | Установленные NLP-пакеты и встроенный suffix snapshot; DNS/connect запрещены в benchmark |
| Загрузка скана в обход текста | Файлы/мультимодальные запросы блокируются при включённом пилоте |

В E2E используется только loopback HTTP mock, который сохраняет фактические
байты запросов в память тестового процесса. Проверяется отсутствие оригиналов
в этих байтах. CRM/почта/бронирование представлены локальными имитациями, реальных
отправок и изменений нет. Помимо fakeredis выполнены проверки настоящего Redis
7.0.15 в Linux-контейнере: TTL, ciphertext, corruption, отдельный процесс,
параллельные сессии и отказ соединения. Основной Redis LocalOS не изменялся.
03.11.2026 для нового выделенного PII Redis дополнительно проверены ACL,
шифрование, expiry, corruption и безопасный отказ/восстановление.

## Оставшиеся риски

1. Исходные арабские/смешанные пропуски исправлены контекстными правилами;
   публичные названия сохраняются при корректном серверном PublicSpan.
   Произвольные имена вне проверенных конструкций, написания в нижнем регистре
   и косвенная идентификация всё ещё не имеют гарантии покрытия. Метрики — [benchmark](benchmark.md).
   Одинаково замаскированные имена не доказывают одинаковую личность.
2. Поиск PII не гарантирует устранения косвенной идентификации по редкой услуге,
   времени, месту или комбинации обстоятельств. Сначала нужно минимизировать
   контекст и передавать агрегаты/разрешённые структурные поля.
3. История LocalOS, исходные файлы, существующие логи, SpeechKit, TTS, поиск,
   публикации и остальные внешние интеграции этим пилотом не обезличиваются.
   Не проведён общий аудит исторических данных, мониторинга и сетевого egress.
4. Общий runtime имеет одну NLP-полосу, ограниченное ожидание, watchdog 10 секунд
   и контроль worker со стороны Gunicorn. Проверены завершение зависшего worker
   и безопасное восстановление; длительный многочасовой soak ещё не выполнен.
   Старый локальный процессный путь не имеет этих гарантий; подключённые пять
   consumers настроены на общий процесс через клиентский файл.
5. Общий runtime проверен на VPS с квотой 0.5 CPU / 640 MiB: пик 551.4 MiB,
   одна модельная полоса. После подключения пяти consumers NLP-модели в них
   не загружены. При пересоздании контейнеров нужны private-сеть и клиентский
   mount из Compose-фрагмента. Он уже включён в автоматический `COMPOSE_FILE` VPS;
   при явном переопределении списка файлов профиль нужно сохранить.
   Замеры 03.11 без admission получили 1.9% busy при четырёх клиентах и 50.6%
   при восьми. В приёмке 04.11 лимит ограничил перегрузку; при обычных 8 запросах/с
   прошли все 240 запросов. Четыре cold-start busy исправлены прогревом до готовности;
   два повторных холодных запуска обработали 240/240. Смешанный рабочий профиль
   и длительная нагрузка остаются отдельной проверкой до cohort.
6. Пилот ограничивает payload 100 000 символами и 2000 сущностями. Защита от больших
   запросов/злоупотребления дополнительно зависит от существующих лимитов LocalOS.
7. TTL Redis — логическое удаление. AOF/backup могут содержать старый ciphertext;
   нужен отдельный регламент ключей и хранения резервных копий. Ключ не хранится
   вместе с Redis и не переиспользует legacy-адаптер с небезопасным base64 fallback.
8. Серверная allowlist назначена семи проверенным контрактам. Для остальных
   `pii_restore_fields` пуст; новый инструмент требует отдельной проверки назначения
   каждого поля. Вложенные объекты в разрешённом текстовом поле не восстанавливаются.
9. В адаптере используется приватный `_tracer` закреплённой версии piighost:
   обновление требует повторного теста отсутствия payload-трассировок.
10. Выключенный флаг сохраняет старое поведение приложения. Отключать защиту у
    будущего рабочего cohort без остановки чувствительных AI-задач небезопасно.
11. PublicSpan принимается только как серверный объект, с tenant и точным
    диапазоном; модельная/пользовательская подпись Company не создаёт исключение.
    Источник и права проверяет вызывающий сервис, а не наличие source_id само по
    себе. Для планировщика текстового Оператора источник теперь проверяется через
    доступ к бизнесу и связанный сохранённый снимок карты. Универсальное подключение
    ко всем остальным prompt builders не выполнялось; без контекста действует
    консервативная защита.

04.11.2026 добавлены общий лимит 10 protect/с и лимит 4 protect/с на бизнес,
burst 4. Квота проверяется перед NLP; HTTP 429 не приводит к вызову провайдера
или plaintext fallback. Восстановление уже выданных токенов не расходует эту квоту.
Счётчики находятся в единственном worker процесса, сбрасываются при его перезапуске
и не являются долговечной системой биллинга/anti-abuse. Память ограничена 1024
HMAC-идентификаторами бизнеса с очисткой неактивных записей.
До готовности v3 выполняет только синтетический RU/EN protect/restore. Ошибка
прогрева блокирует запуск; реальные строки в прогрев не передаются.
[Отчёт и границы приёмки](operator-acceptance-20261104.md).

Синтетические тесты не доказывают полную защиту, необратимую анонимность или
юридическое соответствие. Изменений production-схемы или production-данных нет.
