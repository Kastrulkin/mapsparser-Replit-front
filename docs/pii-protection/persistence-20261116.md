# Сохранение PII-настройки при пересоздании — 16.11.2026

Статус: **FIX_PROVEN**, текущий согласованный объём завершён. Защита текстового
Оператора остаётся включённой: `operator_text`, `enforce`.

## Причина

Рабочий outreach-worker был создан 15.11 из
`/opt/seo-app/backups/vr-yougile-marker-20261115/compose.release.private.json`.
Этот сохранённый файл содержал старый выключенный env и только client.json mount.
Канонический текущий профиль был правильным, но не участвовал в этой команде.
Скопированный впоследствии activation.json жил в слое контейнера и терялся при
следующем пересоздании. Серверный marker блокировал защищённый вход при отсутствии
конфигурации; передачи открытого текста как fallback не было.

## Исправление

В используемом файле все пять защищённых сервисов теперь задают `extends` на
актуальный `docker/pii-runtime/compose.client.fragment.yml`. Зафиксированные копии
шести policy-переменных и двух privacy mounts удалены из child-описаний, поэтому
они больше не перекрывают актуальную политику. Значения остальных параметров нормализованной
конфигурации сохранены, что проверено до применения.

Добавлен `scripts/ensure_pii_compose_inheritance.py`: безопасная проверка или
`--apply`, без автоматического перезапуска. Он работает с защищёнными JSON,
не выводит их содержимое, делает точную исходную копию и отказывает при постороннем
изменении конфигурации. Исходная копия этой выкладки:
`/opt/seo-app/backups/vr-yougile-marker-20261115/compose.release.private.before-pii-20261116T121453Z.json`.
Активный каталог конфигурации отмечен `.keep`.

В `scripts/deploy_backend_src.sh` сохранён server-only `.activation-required`
при `rsync --delete`; соответствующая проверка выполнена на синтетических деревьях.
Инструкции закреплены в AGENTS.md и серверном runbook.
