## Подготовлено

Поэтапное включение для общего текстового `operator_chat_service.process_chat`
(веб и owner-бот Telegram). Контекст назначается серверным обработчиком,
не зависит от присланного клиентом `channel`, передаётся в shadow-контекст и
очищается при завершении/исключении. Другие AI-функции, голос, файлы и фоновые
задачи вне этого обработчика не включаются автоматически.

Отдельный защищённый файл активации содержит только `version`, `enabled`,
`scope=operator_text`, `mode=enforce|blocked`. Он не меняет четырёхполейный
секретный API-конфиг. Для текущих контейнеров подготовлены защищённые копии с
обязательным marker; будущий Compose использует read-only bind и
`create_host_path:false`. Явное значение файла имеет приоритет над прежним
environment. Отсутствующий/повреждённый обязательный файл блокирует запрос.
После включения аварийный режим — `enabled=true, mode=blocked`, без отката
на отправку открытого текста.

Подготовлена проверяемая выкладка трёх файлов с исходными SHA, резервными копиями,
перезапуском пяти процессов по очереди, проверкой перед включением и синтетической
подменой/восстановлением из каждого контейнера. Runtime должен изменить только
`synthetic_only: true → false`, сохранив ключи, ACL, TTL и квоты 10/4 protect/с.
Скрипты подготовки находятся в `/private/tmp/localos-pii-enable-20261104` локально
и `/opt/seo-app/.deploy/pii-enable-20261104` на VPS. `activate.py` на VPS ещё
не загружен и не запускался; перед продолжением нужны свежие проверки и хэши.
