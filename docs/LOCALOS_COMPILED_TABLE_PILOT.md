# Compiled-проверка таблицы

Статус на 6 сентября 2026: **internal**, локальный пакет и изолированный staging. Production-включение и пользовательская приёмка не выполнены. Фактический выпуск: [отчёт реализации](LOCALOS_IMPLEMENTATION_STATUS_2026-09-06.md).

## Пользовательский сценарий

Владелец загружает CSV/TSV или вставляет таблицу, сопоставляет колонки, выбирает обязательные значения и ключ поиска дубликатов. Затем задаёт ожидаемый результат для строк собственного примера. Модель создаёт Python-программу; отдельный runner проверяет её исходник на этом примере и сравнивает результат с независимыми правилами. После проверки пользователь утверждает именованную версию и загружает рабочую таблицу для запуска.

Новые данные запуска не требуют обращения к модели. Изменение правил, примеров или схемы создаёт кандидата. Прежняя утверждённая версия сохраняется до отдельного утверждения нового кандидата. Пользователь может вернуться к ней. История показывает исходные номера строк, причины ошибок и CSV результата; технические source/manifest/JSON раскрываются отдельно.

Это формальная проверка данных. Правила, требующие нового языкового суждения при каждом запуске, в данный пилот не входят. Загруженный пример сохраняется в неизменяемой версии: интерфейс предлагает использовать вымышленные данные.

## Контракт и ограничения

- Пилот использует `localos.sheet_validate_dedupe_report.v1` и отдельный `table_contract.version`. Новые версии конструктора создают контракт **2**. Контракт **1** продолжает исполняться с прежней семантикой.
- Значения ячеек остаются строками, включая `001` и `0`. Заголовки уникальны после удаления пробелов по краям; mapping колонок однозначен. Ограничения: 200 строк, 20 колонок, 80 символов заголовка, 1000 символов ячейки, 20 KiB JSON-входа. Управляющий разделитель U+001F запрещён.
- Пустое обязательное значение исключает строку. Для поиска дубликатов выбранные значения сравниваются после trim/lowercase; первая подходящая строка сохраняется. В контракте 2 дубликат входит в `errors` с `code=duplicate` и исходным номером строки, а счётчик `invalid` считает только строки с ошибками обязательных значений. В контракте 1 дубликаты отражаются только отдельным счётчиком.
- Артефакт ограничен 192 KiB в совокупности: source, manifest и fixtures. Его digest закрепляет исходник, правила, схему, примеры и runtime/image digest. Генератор не может заменить заданный приложением контракт.
- Генерация: один новый запрос в 60 секунд, максимум 20 за 24 часа на пользователя и бизнес. Сетевой повтор с тем же ключом и содержимым возвращает прежний результат; изменение содержимого с прежним ключом конфликтует. Неопределённый зависший результат не вызывает модель повторно под тем же ключом.
- Снимки входа: до 100 неистёкших снимков на пользователя и бизнес. Снимок закрепляет пользователя, бизнес, blueprint, схему и hash; произвольного доступа к БД или сторонним источникам у runner нет.

## Утверждение и выполнение

Источник истины для рабочей compiled-версии — защищённый `agent_blueprints.compiled_approved_version_id`. Generic `status=draft` сам по себе не означает, что утверждённая compiled-программа не готова; UI должен показывать её отдельный фактический статус. Paused/archived запрещают новые выполнения.

Проверка кандидата разрешена в `checking`, `needs_fix`, `ready_approval`. Утверждённую версию нельзя изменить поздним preview. Утверждение сверяет artifact/fixture digest и сохраняет pointer атомарно. Исторические approved-версии без защищённого pointer не активируются миграцией автоматически: доступ к истории сохраняется, для исполнения требуется явное актуальное утверждение.

Каждый compiled endpoint проверяет обычную сессию без impersonation и текущее состояние аккаунта в БД. Перед сохранением результата модели права проверяются повторно. Admission блокирует blueprint/версию и snapshot, затем атомарно фиксирует run, reservation и audit. Worker повторно проверяет действующий аккаунт, доступ, cohort, pointer и артефакт.

Ожидание runner не держит PostgreSQL-транзакцию. Результат фиксируется отдельной транзакцией с lease token; устаревший исполнитель не может завершить чужую попытку. Повтор уже принятого намерения возвращает существующий журнал, в том числе после удаления snapshot; новый ключ требует доступного входа. Это не разрешение исполнять истёкший snapshot заново.

## Данные и runner

Срок snapshot — семь дней с создания. Периодическая maintenance-очистка удаляет истёкший snapshot и копии исходных строк в terminal run, оставляя отчёт, hashes и audit. Истёкшие задания в очереди завершаются с `input_expired` и освобождением reservation. Работающий run откладывает очистку до окончания или штатного восстановления lease. Fixtures и preview-примеры принадлежат версии программы и под эту очистку не подпадают. Срок резервных копий БД регулируется отдельно; очистка online-таблиц не переписывает уже созданные backups.

Runner имеет отдельную внутреннюю сеть без сети PostgreSQL, публичного порта, host mounts и Docker socket. Он не получает DB/provider credentials. Два параллельных запроса, ограниченные CPU/RAM/PID/time/output и отдельный дочерний процесс с очищенным окружением сохраняют границу выполнения. HMAC, nonce и digest защищают транспорт; они не заменяют проверку фактического образа на Docker-host. См. [runbook runner](../docker/compiled-script-runner/README.md).

Ошибки программы и выходной схемы возвращают подписанный отказ и ведут к исправлению кандидата. Недоступность, перегрузка и timeout runtime имеют отдельные коды; повтор чистого исполнения ограничен числом попыток. Обычные логи не должны содержать рабочую таблицу.

## Включение и оставшаяся работа

`COMPILED_SCRIPT_PREVIEW_ENABLED` и `COMPILED_SCRIPT_EXECUTE_ENABLED` выключены по умолчанию; оба требуют backend cohort `COMPILED_SCRIPT_PILOT_BUSINESS_IDS`. Перед включением нужен проверенный pinned image. Ручной исходник и generic Python доступны только при отдельном `COMPILED_SCRIPT_ADVANCED_ENABLED` и superadmin; пользовательский путь принимает формальную таблицу и создаёт source моделью.

Изолированный staging smoke с ручным исходником доказывает API/approval/queue/runner/report, а не качество генерации модели или пользовательский пилот. Обязательные дальнейшие условия: настоящий пользовательский preview/run, оценка UX, независимый обзор sandbox перед общей эксплуатацией. Зарегистрированный read-only источник, расписания, второй пилот и предложения внешних действий следуют после этих этапов. Утверждение программы не означает разрешение отправлять, публиковать или платить.

Основные реализации: `src/services/compiled_table_contract.py`, `compiled_generation_admission.py`, `compiled_input_snapshots.py`, `agent_run_admission.py`, `agent_run_queue.py`, `compiled_script_artifact.py`, `compiled_script_runtime.py`; HTTP — `src/api/agent_blueprints_api.py`; UI — `frontend/src/components/agents/CompiledScriptBuilder.tsx`.
