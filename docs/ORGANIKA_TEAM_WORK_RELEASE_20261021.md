# Планёрки, голос и журнал: совместимый выпуск 21.10.2026

Статус: available для действующей подписки любого тарифа при включённом флаге. MAX — beta: реальные авторизация, клиент и доставка ещё не приняты, MAX остаётся выключен.

## Поведение

- Владелец пишет или надиктовывает фокус дня, выбирает сотрудников, проверяет текст и подтверждает передачу. Сотрудник видит свои поручения, согласованные подсказки и отмечает выполнение.
- Сотрудник сообщает наблюдение текстом или голосом. В миниаппе распознанный текст проверяется до сохранения; в боте явный префикс «В журнал: …» сохраняет наблюдение без платной интерпретации и без выполнения команд из цитаты.
- Владелец разбирает запись, назначает внутреннюю задачу или готовит поиск исполнителя. В поиске проверяются исходная запись, её версия, география, условия, объём и расходы. До подтверждения задача поиска не создаётся.
- Поиск переиспользует `outreach_continuation` и существующий реестр компаний. Разрешены список либо список с черновиками. Отправки и договорённости отдельно согласуются; сценарий журнала не включает auto_send.
- Новые клиенты включают уведомления журнала сами. Существующие предпочтения сохранены. История доступна для чтения после окончания подписки; новые записи и решения блокируются.

## Состав и совместимость

Общая ветка содержала старый исполнитель поиска без `prepare_new_task_approval` и `confirm_task_start`. Восстановлены уже развёрнутый исполнитель и его зависимости: оценка кредитов, версия источника поиска, чтение сайтов через существующий OpenClaw, просмотр отправки, журнал результатов и представление ответа. Совместимые части native campaign approval и очереди перенесены точечно, сохранив защиту разрешений и повторов. Это синхронизация существующего маршрута, без нового коннектора или второй очереди.

Фронтенд общий для веба, Telegram и MAX. Добавлены проверка голосовой записи, прямое исправление наблюдения, внутреннее поручение и предварительный просмотр поиска, ограниченное ожидание API и понятные сетевые ошибки. Индикатор «Отправлено» требует идентификатора сообщения провайдера.

## Выкладка

`docker-compose.yml` передаёт `OPERATOR_TEAM_WORK_ENABLED` в app, worker и telegram-bot; operator-worker наследует worker. По умолчанию флаг выключен. На действующем сервере уже установлены `OPERATOR_TEAM_WORK_ENABLED=true` и `OPERATOR_DAY_BRIEF_DELIVERY_ENABLED=true`. Смена окружения требует частичного пересоздания соответствующих сервисов с сохранением текущих образов. Не переносить private .env в Git.

Миграций этого выпуска нет. Существующие миграции журнала, разбора, планёрок, operator_async_jobs и agent_action_ledger должны быть применены. Не изменять подписки, клиентские записи и расписания при выкладке.

При откате флага новые клиенты теряют новый ввод, ранее включённые пилоты сохраняют свой маршрут. Остановка поиска выполняется отдельно в Партнёрствах: закрытие записи журнала само по себе не отменяет уже подтверждённый поиск.

## Проверка и ограничения

Проверки используют отдельный PostgreSQL со случайными схемами, реальные права и подписки. Есть настоящий вызов native подтверждения из журнала: создаётся одна задача, ссылка сохраняется, повтор не создаёт вторую. Внешние провайдеры и расходные действия в тестах заменены контролируемыми ответами.

Голос ранее проверен настоящим SpeechKit на синтетической записи; тестовая планёрка доставлена только разрешённому тестовому получателю Telegram. Временные аккаунты отключены. При этой синхронизации сообщений, поисков, оплат и production-записей не выполняли.

Физический микрофон телефона и настоящий MAX требуют отдельной приёмки. Приватные отчёты, письма клиентов, базы, токены и .env в Git не включены. Не считать этот выпуск полной синхронизацией всех прочих незакоммиченных изменений production.

## Результат проверки пакета

- Общий прогон: 336 backend-проверок, без пропущенных проверок в выбранном наборе.
- Интерфейс: 26 проверок, сборка frontend выполнена.
- Набор включает PostgreSQL-проверки обычных сотрудников, все действующие тарифы, Telegram/MAX, действительное native подтверждение поиска, идемпотентность, устаревшие записи, кредиты, очередь, отзыв разрешения и восстановление задач.
- Проверки запускаются с `OPERATOR_VOICE_TEST_DSN` и `OUTREACH_TEST_DSN`, указывающими только на одноразовый локальный PostgreSQL. Ни .env production, ни клиентские записи тестам не нужны.
- Внешние HTTP-вызовы и распознавание/генерация в этом прогоне заменены контролируемыми результатами; ранее выполненные живые проверки описаны выше отдельно.
- Соседний набор ограничений отправки: 55 проверок. Две проверки исходной структуры обновлены под уже существующую делегацию в SerializedDispatchLoop; порядок синхронизации ответов, обработка отсутствия ответа и ограничения списка бизнесов проверяются в реальном цикле. Сам worker не менялся.
