# Клиентское общение в автоматизации

Маршрут: `/dashboard/agents?section=clients`.

Раздел использует существующие AIAgentSettings, API управления AIAgents и настройки бизнеса. После сохранения обновляет бизнес в контексте кабинета. Вкладка проверки использует EmployeeChatTest с dry_run, рабочие диалоги — ChatsPage с существующими паузой и историей. Смена бизнеса перемонтирует раздел; несовпадающий контекст скрывает настройки.

CompiledScriptBuilder и обработчики входящих сообщений не изменены. Новая навигация не включает агента и не переносит данные автоматически. Старая ссылка из настроек ведёт непосредственно в клиентское общение.

Ограничения: это перенос управления существующим механизмом, без реализации CRM-записи и реактивации. Существующее расхождение между ai_agents_config и legacy-полями, читаемыми ai_agent.get_agent_config, требует отдельной проверки перед расширением runtime. Telegram сохраняет существующий выбор blueprint/fallback; новая точка входа не меняет маршрутизацию. Реальные каналы и подключения должны пройти отдельную production-проверку.

## Проверка реальных настроек — 30.10.2026

Обнаружен разрыв: UI сохранял ai_agents_config, а get_agent_config читал legacy-поля. Добавлен resolver services/client_agent_settings.py, используется реальным обработчиком и native sandbox; выбор модели учитывает сохранённую роль. Язык и тон явно включены в prompt, gate учитывает сохранённое включение. Native sandbox больше не возвращает ответ другого bridge до применения настроек. Лимит AI возвращает 429.

На Новамеде транзакционно проверено сохранение → resolver → prompt (язык en, friendly, контрольное ограничение), выполнен rollback и проверено отсутствие изменений. Owner API сохранения вернул 402 из-за тарифа; реальный AI sandbox вернул gigachat_budget_exceeded (429 после исправления). Полное успешное сохранение через owner API и реальная генерация ответа пока не подтверждены. Внешних сообщений не было. Временная смена конфигурации другого бизнеса была отклонена auto-review и не выполнялась.
