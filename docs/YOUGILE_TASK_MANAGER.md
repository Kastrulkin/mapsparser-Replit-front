# YouGile как таск-менеджер LocalOS

Статус: beta, подключение доступно в production с 10 ноября 2026.

Пользователь: владелец бизнеса подключает свою команду YouGile через
«Настройки → Подключения → YouGile», выбирает проект, доску и колонку для новых
поручений. Сотрудники с доступом к бизнесу читают задачи. Пользователи с правом
операционной работы готовят создание/завершение задач и подтверждают точное действие.
Тот же контур доступен Оператору в web, Telegram и MAX через общий каталог tools.

Критерии готовности:

1. Ключ API проверяется через YouGile, шифруется существующим Fernet-хранилищем
   и не возвращается в API/браузер. Без явного ключа шифрования подключение запрещено.
2. Подключение и выбранная доска изолированы по business_id. Проект, доска, колонка,
   исполнители и задачи проверяются по актуальным данным провайдера.
3. Подключение и чтение не создают задач. Изменения проходят существующие
   Operator approvals и Action Orchestrator. Изменение подключения/доски после
   preview отменяет прежнее подтверждение.
4. Чтение пагинируется с явными лимитами. Сбой не маскируется пустым списком.
5. Повтор подтверждения не создаёт дубль. После неизвестного результата записи
   автоматического повтора нет. Отключение стирает локальный ключ, не удаляет задачи.
6. UI показывает понятный следующий шаг, ошибки и пустое состояние; смена бизнеса
   не показывает старые данные и не применяет запоздавшие ответы.
7. Локальные тесты подтверждают права, шифрование, границы доски, preview,
   повтор, неизвестный результат и ошибки провайдера; frontend собирается.

Официальный контракт: https://yougile.com/api/ (REST API v2, Bearer API key).
Поддерживается облако https://ru.yougile.com/api-v2; произвольные серверы и
самостоятельные установки не принимаются. Ключ создаётся в YouGile; пароль
YouGile в LocalOS не передаётся. Назначение пользователя, добавленного через
отдел, пока требует явного прямого членства в выбранном проекте.

Служебная интеграция `outreach_yougile_sync_service` с серверным auth_ref остаётся
отдельным существующим сценарием; клиентский ключ не подменяет её и не включает
автоматические отправки. Webhooks, фоновая синхронизация, автоматические напоминания
в ботах и массовые операции в текущую приёмку не входят.

## API и включение

- `GET /api/business/<id>/yougile/status`: состояние и права пользователя.
- `POST /api/business/<id>/yougile/connection`: проверка и сохранение ключа.
- `DELETE /api/business/<id>/yougile/connection`: стирание локального ключа.
- `GET /api/business/<id>/yougile/catalog`: проекты; с `project_id` — доски;
  с `project_id` и `board_id` — колонки.
- `PUT /api/business/<id>/yougile/selection`: выбор проекта, доски и колонки.
- `GET /api/business/<id>/yougile/tasks`: актуальные задачи выбранной доски.
- `POST /api/business/<id>/yougile/tasks/preview`: подготовка одной задачи
  (`operation=create`, `title`, `description`, `assigned`, `deadline`) либо
  завершения (`operation=complete`, `task_id`). Возвращает Operator approval.
- Подтверждение и отказ: существующие `/api/operator/actions/<id>/confirm`
  и `/reject`, с тем же бизнесом и пользователем.

Дата срока требует явного часового пояса, например `2026-11-03T18:00:00+03:00`.
Отсутствующий срок и исполнитель показываются явно и не придумываются.
Колонка, исполнитель и полный текст видны перед подтверждением.

Настройки: `YOUGILE_CLIENT_ENABLED=true`, обязательный
`EXTERNAL_AUTH_SECRET_KEY`, применённая миграция `20261031_yougile_tasks`.
Для диалогового выбора tools нужен существующий `OPERATOR_TOOL_LOOP_ENABLED`
и доступ к управлению по тарифу. Секрет клиента не хранится в переменных среды
и не использует служебный `YOUGILE_API_KEY`.

Перед production нужны согласованная выкладка, проверка Alembic-линии и
резервная копия БД согласно AGENTS.md, затем реальная приёмка на отдельной
доске клиента. Автоматические внешние записи при подключении не включаются.

## Локальная приёмка 31 октября 2026

- 37 Python-тестов (YouGile и общий tool loop) прошли на изолированной
  PostgreSQL `127.0.0.1:55531`, с контрактными ответами YouGile.
- 9 frontend-тестов (панель YouGile и регрессия Trello) прошли.
- Полный frontend build и typecheck прошли; Ruff F и diff checks прошли.
- В локальном браузере проверены форма, выбор исполнителя, фокус на preview,
  подтверждение и появление тестовой задачи. Внешние записи не выполнялись.
- Реальный API-ключ клиента, живое создание задачи и доставка уведомлений
  пользователям YouGile не проверялись. Нативные MAX/Telegram в этой приёмке
  не использовались; общий путь до approval проверен для трёх каналов.

В исходной базе этой ветки отсутствует существующий модуль
`services.agent_outreach_continuation`, который импортирует общий Operator.
Тесты нового адаптера изолируют эту границу; дополнительная проверка настоящей
регистрации Operator/handler прошла с fallback-путём к существующим исходникам
основной рабочей папки только для отсутствующего модуля. Новый модуль не
копировался в ветку и несвязанный код не менялся. Для полной приёмки приложения
нужна актуальная согласованная база исходников, как и для предыдущих выпусков.

## Production-проверка 10 ноября 2026

Вход: https://localos.pro/dashboard/settings?focus=yougile

Форма подключения проверена в живом кабинете. На отдельном бизнесе LocalOS QA
с существующим служебным ключом проверены сохранение зашифрованного ключа,
выбор проекта/доски/колонки и чтение: 12 проектов, 1 доска, 11 колонок,
1556 задач, 1 доступный исполнитель. Доступ без авторизации отклонён.
Проверочное подключение удалено после проверки. Клиентские задачи не создавались,
внешние записи не выполнялись. Живое создание/завершение задач остаётся непроверенным.

Перед миграцией сделана полная резервная копия PostgreSQL с проверкой каталога
pg_restore. Миграция продолжает актуальную линию `20261105_prepared_cabinet`.
Интерфейс собран поверх текущего production, чтобы сохранить более новые экраны.
Существующее наблюдение за задачами через `operator_yougile` сохранено отдельно
от нового `operator_yougile_tasks`. После обновления Telegram-бот healthy.

Чтение задач использует страницы до 1000 записей, чтобы уменьшить влияние
перестановки задач между запросами; неполные и дублирующиеся ответы всё ещё
отклоняются. Общий предел коллекции — 5000 записей. Webhooks и новые
автоматические напоминания этим выпуском не добавлялись.
