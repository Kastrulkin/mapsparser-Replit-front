Добавлен read-only адаптер `yandex_public_disk`: принимает только HTTPS публичные корневые ссылки Яндекса, читает через Public Resources API, сохраняет стабильный resource_id и редакцию, обрабатывает пагинацию, проверяет каждое перенаправление скачивания на HTTPS-сервер Яндекса. Видео не скачивает. Подготовка источника использует существующие права владельца и версию подключения. OAuth-подключения сохраняют прежнее поведение.

Обнаружены и устранены две причины, мешавшие фактическому импорту: долгие общие фоновые задачи задерживали очередь; S3-хранилище пыталось работать через недоступный глобальный прокси. Импорт теперь имеет отдельный поток внутри обычного worker и забирает только задания импорта из существующей долговечной очереди. Временные ошибки повторяются с увеличением интервала, страницы обхода имеют приоритет внутри очереди бизнеса. `MEDIA_S3_HTTP_PROXY=direct` включает проверенное прямое подключение к тому же штатному хранилищу; глобальный прокси остальных функций не изменяется.

Production: точечно обновлены backend-файлы, флаги включены для трёх перечисленных бизнесов, перезапущены только app/worker. Схема БД не менялась. Существующие таблицы импорта присутствовали до изменений. Копии файлов и настроек для отката находятся на сервере в `/opt/seo-app/.deploy/public-disks-20260921/rollback` (настройки содержат секреты и не публикуются).

Проверены разрешённые хосты/пути, пагинация, исключение личных документов, запрет скачивания видео, изменение редакции, запрет чужого redirect и настройка S3. Проверены реальная изоляция фоновой/голосовой очередей, повтор обработки уже импортированных фотографий с тем же photo_asset_id и чтение изображений из хранилища. HTTP приложения — 200. Откат подключения: отключить соответствующий источник штатным действием; медиатека и история сохраняются. Откат файлов: восстановить согласованный комплект из rollback и прежние значения только изменённых флагов, затем перезапустить app/worker. Не восстанавливать старый compose или .env целиком поверх более поздних изменений.
