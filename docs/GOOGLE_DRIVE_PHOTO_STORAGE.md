# Google Диск для фотографий LocalOS

Статус: beta, выпуск рабочего пилота. Реальное подключение требует OAuth-приложения Google и согласия владельца бизнеса. Интеграция Google Sheets и Google Business Profile не используется.

Владелец открывает Оператор → Настройки рабочего пилота → Подключить Google Диск. Можно подключить Google, Яндекс или оба хранилища. Сначала фото сохраняется в LocalOS; после явного назначения фотографии материалу для публикации оно отправляется в подключённые хранилища. Финансовые документы и расписания туда автоматически не попадают. При подключении синхронизируются уже классифицированные фотографии (до 1000 за запрос).

## OAuth приложения

1. В Google Cloud создать OAuth client типа Web application, включить Google Drive API и настроить экран согласия. Для тестового приложения добавить пользователей в test users; для постоянной эксплуатации перевести приложение в Production согласно требованиям Google.
2. Зарегистрировать точный redirect URI:
   `https://localos.pro/api/operator/google-drive/callback`
3. Администратор LocalOS открывает https://localos.pro/dashboard/settings/storage и сохраняет Client ID и Client Secret в форме Google Диска. Секрет передаётся по HTTPS и хранится зашифрованным; API не возвращает его. Настройки общие для платформы, владельцы бизнесов отдельно подключают свои Диски. Переменные `GOOGLE_DRIVE_CLIENT_ID` / `GOOGLE_DRIVE_CLIENT_SECRET` остаются запасным источником, если записи в интерфейсе ещё нет. Нужен постоянный `EXTERNAL_AUTH_SECRET_KEY` на сервере; секреты не помещать в репозиторий или переписку.
4. Применить Alembic `20260915_storage_oauth` (включает `20260914_google_drive`) после резервной копии PostgreSQL. Пересоздать затронутые Compose-сервисы для передачи переменных окружения. Функция ограничена существующим `OPERATOR_WORKDAY_BUSINESS_IDS`.
5. Владелец подключает аккаунт через внешний браузер. Для Telegram Mini App, если Google запрещает вход во встроенном браузере, использовать веб-версию LocalOS в системном браузере.

Запрашивается только `https://www.googleapis.com/auth/drive.file`, `access_type=offline`, `prompt=consent`. OAuth state хранится хешированным, живёт 10 минут, одноразовый, привязан к владельцу и бизнесу. Срок state защищает вход и не ограничивает срок сохранённых фотографий. Refresh token зашифрован на сервере; access token получается перед заданием. `invalid_grant` переводит подключение в «доступ отозван».

## Поведение и ограничения

Папки: `LocalOS/<business_id>/<YYYY-MM-DD>`, фотографии имеют идентификатор и версию в имени. API не публикует файлы и не добавляет общедоступные разрешения. Контент-план хранит прежние photo_asset_id.

До создания файла или папки Google ID сохраняется и фиксируется в PostgreSQL. Повтор задания использует тот же ID; MD5 проверяет результат неопределённой загрузки. Изменённые пользователем и удалённые файлы автоматически не перезаписываются. Отключение сериализуется с текущей загрузкой, отменяет старые задания и сохраняет все материалы. Новое OAuth-подключение имеет новую версию и отдельную папку LocalOS; файлы прежнего подключения не удаляются и не переиспользуются, поскольку пользователь мог выбрать другой аккаунт.

Реальные OAuth и загрузка на клиентский Google Диск ещё требуют настроенного приложения и согласия клиента. Автоматические проверки используют PostgreSQL и подменённые ответы Google, не заменяют этот прогон. Реальный сценарий: подключить → отправить фото → назначить посту → проверить файл/статус → повторить без дубликата → отозвать доступ → проверить сохранность LocalOS → подключить заново.

## Исходники и API

`src/services/google_drive.py`, `src/api/operator_workday_api.py`, `src/services/operator_attachments.py`, `src/services/operator_async_jobs.py`, `frontend/src/components/operator/OperatorWorkdayInput.tsx`, `alembic_migrations/versions/20260914_google_drive.py`.

`GET /api/operator/google-drive/status?business_id=...`; `POST /api/operator/google-drive/connect`, `/disconnect`, `/retry` с `business_id`. Запись подключения только владельцу; чтение и обработка фотографий — действующим участникам пилота по существующим правам.

Документация Google: [OAuth для серверных приложений](https://developers.google.com/identity/protocols/oauth2/web-server), [ограничения доступа drive.file](https://developers.google.com/workspace/drive/api/guides/api-specific-auth), [предварительное создание ID](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/generateIds).

## Настройки Яндекса на той же странице

Создать приложение на https://oauth.yandex.ru/ с правом `cloud_api:disk.app_folder` и callback `https://localos.pro/api/operator/disk/callback`. Сохранить его Client ID и Secret в форме Яндекс Диска на странице `/dashboard/settings/storage`. Настройки немедленно доступны сайту и очередям. На уровне провайдера приложение ограничено папкой `Приложения/<имя приложения>`; произвольная существующая папка не выбирается.

Администратор может менять секрет без его раскрытия. Пустое поле при сохранении сохраняет прежний секрет. Изменение Client ID требует нового секрета и предварительного отключения всех бизнесов от старого приложения. Обновления защищены версией настроек; `updated_by` и `updated_at` фиксируют автора и время. Страница недоступна менеджерам, владельцам без superadmin и демо-сессиям.
