# Голосовое управление LocalOS

Статус: **beta, выключено по умолчанию**. Программная реализация не означает включение SpeechKit или проверку на настоящих телефонах.

## Поведение

Текст и проверенная расшифровка идут через общий `operator_chat_service` в существующий Operator Core. Диалоги разделены по пользователю, бизнесу и каналу (`web`, `telegram`, `telegram_mini_app`). Изменения бизнеса остаются общими. Каждый запрос имеет идентификатор; повтор с другим текстом отклоняется, повтор того же запроса возвращает прежний результат.

Голос: запись/загрузка → фоновая расшифровка → исправление текста → «Отправить Оператору» → результат. Отправка расшифровки не подтверждает публикацию, платёж или изменение данных. Для защищённых действий остаётся отдельное подтверждение, привязанное к preview. Новый preview той же возможности отменяет предыдущее ожидающее подтверждение в этом диалоге.

На голосовой запрос готовится аудиоответ. На текстовый доступна кнопка «Прослушать». В браузере нет автовоспроизведения. Озвучиваются первые 1000 символов сохранённого ответа без дополнительного LLM-вызова. Telegram получает OGG/Opus, браузеры — MP3. Ошибка TTS не запускает команду повторно.

## Настройки пилота

Настройки одинаковы для app, worker и telegram-bot:

- `OPERATOR_VOICE_INPUT_ENABLED=false`
- `OPERATOR_VOICE_OUTPUT_ENABLED=false`
- `OPERATOR_VOICE_BUSINESS_IDS=` — обязательный список разрешённых бизнесов через запятую.
- `OPERATOR_SPEECHKIT_API_KEY=` — отдельный секрет сервисного аккаунта с правами STT и TTS. Ключи Wordstat не подставляются автоматически.
- `OPERATOR_AUDIO_DIR=/app/operator_audio` — общий приватный каталог, смонтированный из `data/operator_audio` во все три сервиса.

На входе максимум 10 МБ и 120 секунд. Квота на пользователя за скользящие 24 часа: 20 распознаваний и 40 озвучиваний. Это расход SpeechKit, отдельного списания пользовательских кредитов за аудио нет. Существующий биллинг команд не изменён.

Исходники удаляются после успешного распознавания; ошибки и оставшиеся файлы очищаются после 24 часов. Аудиоответы доступны 24 часа. Периодическая очистка выполняется worker. Расшифровка и исправленный текст остаются в истории/журнале. Это политика LocalOS; срок хранения у SpeechKit определяется самим провайдером.

Неопределённый результат отправки запроса в SpeechKit не повторяется автоматически: сохранённая отметка предотвращает повторную оплату неизвестного вызова. При сохранённом ID операции worker возобновляет получение результата. Telegram-доставка восстанавливается по журналу; при сбое между отправкой и фиксацией возможен повтор сообщения с теми же кнопками, но не повтор команды.

## API

Все endpoints требуют текущей авторизации и доступа к бизнесу. Чужие записи и диалоги недоступны, включая запросы со scope ограниченной demo-сессии.

| Endpoint | Назначение |
|---|---|
| `GET /api/operator/audio/config?business_id=…` | Доступность ввода и озвучивания |
| `POST /api/operator/audio/transcriptions` | Multipart `file`, `business_id`, `channel`, `conversation_id`, `request_id`; возвращает `asset_id`, `job_id`, `conversation_id` |
| `GET /api/operator/mobile/jobs/<id>?scope_type=business&scope_id=…` | Статус и результат фонового задания |
| `POST /api/operator/chat` | `message`, `business_id`, `channel`, `conversation_id`, `request_id`, опционально `transcription_id` |
| `POST /api/operator/messages/<id>/speech` | Подготовить/вернуть озвучивание сохранённого ответа |
| `GET /api/operator/audio/<id>` | Защищённая выдача готового аудио, `Cache-Control: private, no-store` |
| `POST /api/operator/audio/<id>/cancel` | Отменить неотправленную запись и её обработку |

Распознавание работает через [SpeechKit AsyncRecognizer v3](https://aistudio.yandex.ru/ru/docs/speechkit/stt-v3/api-ref/AsyncRecognizer/recognizeFile), синтез через [TTS v1](https://aistudio.yandex.ru/ru/docs/speechkit/tts/request). Секреты и URL Telegram с токеном не возвращаются клиентам.

## Проверка и запуск

1. Прогнать `tests/test_operator_voice.py`, `tests/test_operator_voice_pg.py` и регрессии Operator. Для PG задать `OPERATOR_VOICE_TEST_DSN` на отдельную тестовую базу. Тест создаёт/удаляет только случайную схему в этой базе.
2. Прогнать `OperatorVoice.test.tsx`, `TelegramControlPage.test.tsx`, сборку и `frontend/e2e/operator-voice.spec.ts`. Браузерные тесты используют подменённый API, не настоящий SpeechKit.
3. Проверить конфигурацию SpeechKit без вывода ключа. На тестовом бизнесе прогнать 30 реальных русскоязычных записей: ≥27 правильно передают намерение и параметры; после правки все 30 дают ожидаемый результат. Проверить реальный Telegram и Mini App на iOS/Android, Chrome и Safari.
4. Перед production-миграцией: из `/opt/seo-app` сделать `pg_dump` в резервную копию и проверить её чтение. Применить Alembic `20260910_001`. Не переносить несвязанные изменения из рабочего дерева.
5. Подготовить общий `data/operator_audio` с владельцем UID/GID контейнеров (по умолчанию 10001:10001) и правами 0700. Пересобрать образы app/worker/telegram-bot с FFmpeg; обновить frontend стандартным runbook. Все длительные команды — в tmux, серверные команды начинаются с `cd /opt/seo-app`.
6. Включить флаги только для согласованного тестового бизнеса. Проверить `docker compose ps`, логи app/worker/telegram-bot, `curl -I http://localhost:8000`, затем целевые запросы и сохранённые результаты.

Откат: отключить оба флага, отменить незавершённые аудиозадания, сохранить таблицы и текстовый путь. Не откатывать журналы действий и не удалять историю.
